## 4. Развертывание локального окружения

Выполните эти шаги один раз при первой настройке проекта на вашем компьютере.

### Шаг 1. Клонирование репозитория
Откройте терминал, перейдите в рабочую папку и склонируйте проект:
```bash
git clone https://github.com/RafaelPozoyan/UrFU_project
cd UrFU_project
```

### Шаг 2. Создание виртуального окружения (venv)
Создайте изолированное окружение, чтобы библиотеки проекта не конфликтовали с системными:
```bash
python3 -m venv .venv
```

### Шаг 3. Активация окружения
Введите команду активации в терминале в зависимости от вашей операционной системы:
*   **Windows:** `.venv\Scripts\activate`
*   **macOS / Linux:** `source .venv/bin/activate`

> *После активации в начале строки терминала появится маркер окружения: (.venv).*

### Шаг 4. Установка зависимостей
Обновите пакетный менеджер и установите все необходимые библиотеки (включая pandas, numpy, matplotlib, seaborn и ucimlrepo):
```bash
pip3 install --upgrade pip
pip3 install -r requirements.txt
```

## 5. Git Flow: Правила работы в команде

Мы работаем по модели Feature Branches. Прямые коммиты в ветку main строго запрещены. Каждый участник команды делает свою работу в отдельной ветке.

### Схема рабочего процесса (Workflow)

1.  **Обновите локальную ветку main:** Перед началом любой задачи заберите актуальный код с сервера.
    ```bash
    git checkout main
    git pull origin main
    ```
2.  **Создайте рабочую ветку:** Назовите её в соответствии с задачей и вашим ФИО (например, feat/eda_titov_e_v or fix/eda_titov_e_v_import).
    ```bash
    git checkout -b имя-вашей-ветки
    ```
3.  **Разработка и коммиты:** Делайте коммиты логичными и небольшими частями. Пишите понятные комментарии.
    ```bash
    git add .
    git commit -m "Добавил графики распределения признаков с помощью seaborn"
    ```
4.  **Отправка ветки на сервер:**
    ```bash
    git push origin <имя-вашей-ветки>
    ```

## 6. Создание Merge Request (MR) и Командное Ревью

После того как вы отправили свою ветку на GitHub, её необходимо слить с основной веткой через процедуру командного код-ревью.

### Шаги для проверки и слияния кода:
1.  Раз в неделю по текущим заданиям проводится совместная встреча с обсуждением решений.
2.  На встрече выбирается и дорабатывается самое конструктивное решение.
3.  Создается Merge Request (Pull Request).
4.  **Слияние в main:** Вливать код в главную ветку разрешено только после командного одобрения.
